## AI选股思考泄漏修复（对抗性审查落地）
用户贴出今日 AI选股生成内容，发现整段是模型思考草稿被原样发出（"康美特应该怎么处理？""这个要小心""评级怎么分配？"等），且完全没遵守 ###+表格 格式、用 ☆ 当分隔符。

根因：① 之前 GitHub 推送失败，CI 跑旧代码（_strip_thinking 加入前）；② 即便本地弱版 _strip_thinking 也抓不住这批措辞（硬编码拦截词不匹配）。

落地修改（均已本地验证）：
- `prompts/system_stock_picker.txt`：新增【硬性语法约束】，声明"你可能是推理模型，正文仅允许 ###/表格/- 三种语法"，明确自问句即违规。
- `prompts/user_stock_picker.txt`：拆清【编造边界】——点名标的可直接列；行业推断标的须标"板块机会（非当日新闻点名）"且代码须核实、不确定只写名不编码；强制每行评级附依据、给结论不给纠结。
- `stock_report.py`：
  - `_strip_thinking` 仅扩词表（保持通用，不锚定 ###，避免误伤 ## 开头的盘面分析）。
  - 新增 `_sanitize_stock_picks()`：首个 ### 为唯一合法起点→其前全丢；逐行删自问句（句中含 ？+怎么/如何/应该/分配等关键词）+ 元短语；删独立 ☆ 行；无 ###/表格/列表则判失败返 None。
  - 新增 `PICKS_FALLBACK` 降级文案；`call_stock_picker` 校验失败返回降级文案并 `_set_github_output("picks_status","fallback")`，绝不发草稿上 Pages。max_tokens 6144→8000 防截断。
- 验证脚本（mock 不调 API）：泄漏草稿→None→降级文案；合规/混合输出思考被干净剥离、###+表格保留；全部断言通过。

待办：本地改动仍需能连 GitHub 的代理 `git push` 覆盖 CI 旧代码，否则线上还是泄漏版。
